# Sigshell: a local workbench for gene signature scores

**Enrico Adamo and Marco Riva · Software Engineering, Fall 2026**

The `sigscores` R package offers several ways to summarize the expression of a gene signature in each sample. Sigshell makes that workflow usable through a local browser page and an optional Model Context Protocol (MCP) tool server. The application is written in Python, HTML, CSS and JavaScript; the scientific calculations remain in the unmodified R package. A researcher supplies an expression matrix and a gene list, checks whether they align, chooses scoring methods, inspects results, and exports data and a replayable R script. The page runs on the researcher's own computer and does not need an AI account.

The two interfaces call the same Python analysis tools. A validator checks file structure, gene identifiers, missing values and method prerequisites before an R step runs. Each computation launches a fresh `Rscript` process and calls `sigscores`; the output includes tables or plots, the exact input choices, package versions and a session script. This architecture gives the browser the same scientific checks as the MCP interface and makes an interactive session auditable outside either interface.

The most consequential hurdle was preserving **which genes were actually scored**. In the pinned `sigscores` version, a GSVA-based path removes constant or missing rows but can then interpret positional signature indices against the shortened matrix. A constant gene outside an unchanged signature can therefore alter the resulting GSVA scores. We reproduced this with a small R example and compared it with a direct GSVA call. Sigshell refuses the affected method and input combination, explains the reason, and offers an explicit operation to write a cleaned *copy* of the matrix. We chose an explicit copy because removing genes changes the available background and can remove a signature gene; doing so silently would hide a scientific decision. We left the upstream package unchanged and kept the reproduction for its maintainers.

A second challenge was avoiding a polished interface that conceals uncertainty. Some scorer failures inside the package appear as all-`NA` results, so Sigshell retrieves and reports the underlying scorer error. Its significance view names the selected random-gene null and states that the comparison is within a sample, not between clinical groups; the displayed intervals describe the null distribution. The expression-scale field records context but does not pretend to normalize raw counts. These constraints came from reproduced cases, not a blanket restriction on the package's methods.

Reproducibility shaped the product: inputs are copied into a session, random seeds and software versions are recorded, and `session.R` replays the analysis without Sigshell or AI. In our test environment, the vignette's synthetic example gave S1 mean **666.55** and median **736.5**; replaying its exported script produced an identical scores CSV. Automated checks cover the web workflow, recorded R calls, and reproduced findings. The main limitations are installation of the pinned R/Bioconductor stack and the need to test whether the interface saves time in real research workflows. A computational biologist has responded positively to the video demo, and a hands-on usability assessment is the next step.
